# ISS-765 — ~/.local/bin not in path for bash

## Problem (original report, condensed)

Bug (label: bug), filed by the maintainer as a tracking issue:

> Applicable only when installation done through `install.sh`

(The issue title is the report: `~/.local/bin` is not in `PATH` for bash after an `install.sh` install.)

## Resolution

What maintainers/collaborators actually said (verbatim):

> **ladybug-me** (OWNER, 2026-09-20):
> This is satisfied by autostart.sh
>
> **Only point of failure is if a maniac starts the session as tty and then starts plasma shell. God help him**

Closed by ladybug-me within the same second as that comment (closed_at 2026-09-20T06:31:11Z).

Corpus note: with an `install.sh` install, `~/.local/bin` (where `caelestia`, `caelestia-color` etc. are linked) is put on `PATH` by the session autostart script, not by the installer; a session that bypasses the normal login autostart (e.g. starting the shell from a TTY by hand) does not get that PATH entry. The known-good path is to log in through a normal graphical session.
