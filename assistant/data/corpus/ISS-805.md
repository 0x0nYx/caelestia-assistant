## Problem (original report, condensed)

> I just recently updated Caelestia KDE to the recent version v2.4.3 and I have encountered an issue where the lock screen falls back to the built-in lock screen despite the command `kreadconfig6 --file plasmashellrc --group "Shell" --key "ShellPackage"`  outputs correctly as "caelestia.desktop" and the `/usr/lib/kscreenlocker_greet --testing` actually shows the caelestia lock screen.
>
> I checked errors related to kscreenlocker in journalctl and found that the module 'Caelestia.Services" is not found.
>
> Aside from that, I couldn't see the caelestia SDDM theme, not sure if I did something wrong even though the installer's full log says its OK

Troubleshooting the reporter had already done (condensed): re-setting `ShellPackage` via `kwriteconfig6` (reads back correctly), reinstalling v2.4.3 (was working on v2.4.2), `kscreenlocker_greet --testing` works, reboot/relogin does not help. Caelestia version v2.4.3, distro CachyOS.

## Resolution

What maintainers/collaborators actually said (verbatim):

> **ladybug-me** (OWNER, 2026-09-22):
> well.. that's an environment variable issue.
>
> try this & **reboot**:
>
> ```bash
> bash -c "mkdir -p ~/.config/plasma-workspace/env && cat << 'EOF' > ~/.config/plasma-workspace/env/caelestia.sh
> #!/bin/sh
> export QML2_IMPORT_PATH=\"\$HOME/.local/lib/qt6/qml:\$HOME/.config/quickshell/caelestia\${QML2_IMPORT_PATH:+:\$QML2_IMPORT_PATH}\"
> export CAELESTIA_LIB_DIR=\"\$HOME/.local/lib/caelestia\"
> export CAELESTIA_BIN_DIR=\"\$HOME/.local/bin\"
> export CAELESTIA_SHELL_CONFIG=\"\$HOME/.config/quickshell/caelestia/shell.qml\"
> EOF
> chmod +x ~/.config/plasma-workspace/env/caelestia.sh"
> ```

Closed manually by ladybug-me at 2026-09-22T16:03:41Z (state_reason completed; no closing commit).

Corpus note: the v2.4.3 lock-screen fallback with a *correct* `ShellPackage` value (`caelestia.desktop`) and a *passing* `kscreenlocker_greet --testing` was an environment-variable problem — the Plasma startscript `~/.config/plasma-workspace/env/caelestia.sh` (QML2_IMPORT_PATH / CAELESTIA_LIB_DIR / CAELESTIA_BIN_DIR / CAELESTIA_SHELL_CONFIG, chmod +x, then reboot) fixed it, confirmed by the reporter. This is a different root cause from the wrong-ShellPackage / stale-greeter-theme case (see TROUBLESHOOTING.md section 4.1), and the SDDM half of the report was a distro default (CachyOS ships plasmalogin, not sddm) plus a since-fixed dev-branch bug.
