# ISS-120 — Feat: AI-Powered Natural Language Settings Assistant

State: OPEN · opened 2026-07-11 by dr-strange15.

This thread is OPEN: there is no resolution. It is part of the corpus because it defines what the on-device assistant itself may claim to do — no more, no less.

## Proposal (original, condensed)

I think Caelestia-kde-dots is in a unique position to make desktop customization much more approachable by allowing users to configure the shell using natural language.

Instead of manually searching through Nexus or editing configuration files, users could simply describe what they want.

Examples:

- "Make my bar thinner."
- "Move the dock to the left."
- "Increase the blur."
- "Make everything feel more compact."
- "Give the desktop a minimal look."

The assistant would interpret the request, convert it into structured configuration changes, and apply them through Caelestia's existing configuration system.

---

After looking through the project, it feels like most of the pieces already exist.

Caelestia already has:

- AI Assistant
- Ollama integration
- `ConfigObject` architecture
- Live configuration updates
- Nexus settings application

Right now these are mostly independent systems.

Connecting them together could make Caelestia one of the easiest and most intituve desktop environments on whole of linux to customize without introducing an entirely new subsystem.

---

The assistant should never modify configuration files directly.

Instead, it should only request changes through a controlled API.

The overall flow could look something like this:

```text
User
   │
   ▼
AI Assistant
   │
   ▼
Intent Parser
   │
   ▼
Structured Tool Calls
   │
   ▼
ConfigObject / …[truncated]
